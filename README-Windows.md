## 一、快速开始

| 顺序 | 文件 | 作用 |
|---|---|---|
| 1 | `install.bat` | Python→`.venv`→依赖→Chromium→环境验证 |
| 2 | `login.bat` | 扫码登录（真登录校验：无 skey 不落盘）+ 人脸 + 参数核实 + 模板抓取 |
| 3 | `check.bat` | 抢购前只读总检查（**绝不下单**） |
| 4 | `start.bat` | 启动（默认**模拟模式**，不发真实下单请求） |

## 二、双引擎架构（2026-11-01 实测定案）

- **API 引擎（主）**：`snap_up_server.py` 纯 HTTP 并发下单。实测登录态下 do-goods 请求形状合法
  （无签名头返回 `1101001 秒杀尚未开始`，签名当前未强制），沿用九月实战的返回码分类与重试策略。
- **浏览器引擎（兜底）**：`browser_engine.py` Playwright 驱动官方页面点击。do-goods 页面请求层带
  `withSign` 签名+设备指纹；若哪天服务端开始强制校验签名导致 API 引擎被拒，用浏览器引擎接管
  （页面自己签名，我们不伪造任何风控参数）。

## 三、价格红线（最高优先级，三重验证）

价格解析不出来 → 真实模式直接拒绝。绝不转买 109/188 元或其他配置。

## 四、真实抢购操作（例：明天 10:00 场）

```text
1. （可选但推荐）跑一次 check.bat —— 应为 0 失败
2. 用记事本改 settings.json: "runtime" 里的 "mode" 从 "dry" 改为 "real"
3. 09:55 左右双击 start.bat —— 会显示真实模式确认，输入 YES
4. 脚本自动对时 → 09:59:58.5 提前开打 → 并发三地域 → 限流退避 → 成功即停
5. 抢到后自动弹官方付款页 → 你人工支付（程序绝不自动付款）
   超时未付订单会释放；若提示已有未付单，去订单中心处理
```

也可以命令行：`.venv\Scripts\python.exe snap_up_server.py --mode real --real`（还需输入 YES）。
手动指定场次：加 `--at "2026-11-02 15:00:00"`。

## 五、安全与合规

- 不自动支付 / 不绕过验证码、人脸、风控 / 不伪造签名（浏览器引擎=驱动真实页面）
- 408/429 指数退避（1.5→3→6→8s 封顶），连续 5 轮限流安全停止；轮间 0.5s+抖动
- 单账号单订单，成功或未付单立即停止；抓包只存 URL+请求体，绝不存 Cookie/请求头
- `cookies.json`、`config.json`、`logs/` 均已 `.gitignore` 保护

## 六、常见问题

- **1101411 未付单**：已有订单占坑（含"超时但已建单"），先去订单中心支付或取消
- **1101001/1100136 未开抢**：正常回音，脚本会继续重试
- **408 连片**：IP 级限流，脚本自动退避并停止，冷却后再战
- **cookies 失效**（check 显示未登录）：重跑 `login.bat` 扫码（全链路统一 UA，勿改动）
- **页面改版/换期**：重跑 `login.bat` 自动重采参数；`check.bat` 会列出不一致项
